## 0. Scope

This project is a **tap-only** experience. Dropping the accelerometer is the point of the SPA
direction, not a gap in it. Nothing below concerns motion sensors. (For the record, if shake
ever needs to come back to the web build, Godot's `Input.get_accelerometer()` has no web
implementation — [godot-proposals#2526](https://github.com/godotengine/godot-proposals/issues/2526),
open since 2021 — and would need a `JavaScriptBridge` shim. Out of scope here.)

The question this document answers: **can the Godot web export present as a real app on a
phone, with no browser address bar?**

**Answer: yes, via home-screen installation. Not from a browser tab.**

---

## 1. Why installation is the only path on iPhone

The Fullscreen API is not an option on iPhone, and this is not stale information:

* [WebKit bug 206854 — "Add Fullscreen API to iOS"](https://bugs.webkit.org/show_bug.cgi?id=206854)
  is still **NEW**, open since January 2020, with comments as recent as June 2026 confirming
  Safari 27 beta still lacks element fullscreen on iPhone.
* [WebKit bug 212934](https://bugs.webkit.org/show_bug.cgi?id=212934), the webkit-prefixed
  workaround for non-video elements, was closed **WONTFIX on 2026-01-25**.
* [caniuse: Fullscreen API](https://caniuse.com/fullscreen) shows iOS Safari as *partial*
  through 26.5 — partial meaning video elements only.

iPadOS supports it. Android Chrome supports it fully, including in a plain tab. iPhone does not.

So on iPhone, "no address bar" means **standalone display mode via Add to Home Screen**, and
nothing else. Since **iOS 26, every site added to the Home Screen opens as a web app by
default**, standalone, with its own entry in the app switcher
([Apple: Use web apps on iPhone](https://support.apple.com/guide/iphone/use-web-apps-iph3f43e2ca/ios)).

### What you still don't get on iPhone

| Want | Reality |
|---|---|
| No address bar / toolbar | ✅ Yes, when installed to Home Screen |
| Hide the status bar (clock, battery, Dynamic Island) | ❌ No. `display: fullscreen` is not honored on iPhone. You can render *behind* it (§3c) but not remove it. |
| Lock orientation to portrait | ❌ No. [`ScreenOrientation.lock()`](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock) is unsupported on iOS. Must be handled in-engine. |
| One-tap install prompt | ❌ No. `beforeinstallprompt` does not exist on iOS. Manual share-sheet flow only. |

Android Chrome gives you all four.

## 2. User installation steps

### Safari (iOS)
1. Open the URL in **Safari**.
2. Tap **Share** (square with an up arrow).
3. Scroll and tap **Add to Home Screen**.
4. Confirm the **Open as Web App** toggle is **On**.
5. Tap **Add**.

### Chrome (iOS)
1. Open the URL in **Chrome**.
2. Tap the **Share** icon.
3. Tap **Add to Home Screen**.
4. Tap **Add**.

Chrome on iOS gained Add to Home Screen with iOS 16.4
([Chrome Help: Use web apps](https://support.google.com/chrome/answer/9658361)).

> **UNVERIFIED — needs a device test.** Whether a Chrome-installed shortcut launches in true
> standalone mode identically to a Safari-installed one is not settled. Some sources describe
> full web-app installation as a Safari-only path. **This matters for the concert:** if only
> Safari produces a real standalone app, the QR card must say "open in Safari." Test both
> before printing anything.

> **Don't hard-code share-button positions in on-screen hints.** Safari's share button is
> bottom-center in the default tab-bar layout but moves to the top in single-tab layout, and
> Chrome for iOS offers a bottom address bar. Describe the *icon*, not where it sits.

## 3. Developer implementation — Godot specifics

**The critical correction to the earlier draft: do not hand-write `manifest.json`.**

Godot's exporter generates the manifest itself. `_build_pwa()` in
[`platform/web/export/export_plugin.cpp`](https://github.com/godotengine/godot/blob/master/platform/web/export/export_plugin.cpp)
writes a `.manifest.json` from the export preset — name, display, orientation, background
color, and the 144/180/512 icons — alongside a
[service worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API). A
hand-written `manifest.json` is ignored or fights the generated one.

### 3a. Export preset settings

These live in `export_presets.cfg` under `[preset.0.options]` (the Web preset). Enum values
are from the source linked above.

| Key | Current | Target | Notes |
|---|---|---|---|
| `progressive_web_app/enabled` | `false` | **`true`** | Nothing else takes effect until this flips. |
| `progressive_web_app/display` | `1` | `1` | `"Fullscreen,Standalone,Minimal UI,Browser"` → `1` = Standalone. **Already correct.** Do not set `0`; fullscreen is not honored on iPhone. |
| `progressive_web_app/orientation` | `0` | **`2`** | `"Any,Landscape,Portrait"` → `2` = Portrait. Honored on Android, ignored on iOS, but free to set. |
| `progressive_web_app/icon_144x144` | `""` | **set** | |
| `progressive_web_app/icon_180x180` | `""` | **set** | The one iOS uses for the home-screen icon. |
| `progressive_web_app/icon_512x512` | `""` | **set** | |
| `variant/thread_support` | `false` | `false` | **Keep false.** Godot web exports have known issues on Apple devices when threaded; single-threaded avoids them and sidesteps the `SharedArrayBuffer` cross-origin-isolation requirement. |
| `html/custom_html_shell` | `res://exports/index_shell.html` | see §3b | **This file does not exist.** The export fails until it does. |

A manifest with no icons installs with a blurry page screenshot as the home-screen icon.
Portrait source art is in `images/`.

### 3b. The HTML shell

`exports/index_shell.html` is referenced by the preset but is **not in the repo** — `exports/`
contains only `firebase.json`, `ios2/`, and a log file.

Correct procedure:
1. Clear `html/custom_html_shell` and export once.
2. Take Godot's generated `index.html`, save it as `exports/index_shell.html`, commit it.
3. Point the preset back at it and add the tags in §3c to its `<head>`.

This inherits the engine's boot loader rather than reconstructing it by hand. Godot runs the
shell through `_fix_html()` for placeholder substitution, so the generated file is the only
safe starting point.

### 3c. Required `<head>` additions

```html
<!-- Render under the status bar and into the Dynamic Island / notch area -->
<meta name="viewport"
      content="width=device-width, initial-scale=1, viewport-fit=cover, user-scalable=no">

<!-- Legacy standalone signal. The manifest's display:standalone is the modern
     mechanism, but this tag is still required for iOS startup images. Keep both. -->
<meta name="apple-mobile-web-app-capable" content="yes">

<!-- Must pair with viewport-fit=cover above, or you get white bars instead of full bleed -->
<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">

<!-- Name under the home-screen icon -->
<meta name="apple-mobile-web-app-title" content="Holiday Sleigh Bells">

<!-- iOS reads this for the icon in addition to the manifest -->
<link rel="apple-touch-icon" href="icon-180.png">
```

**`viewport-fit=cover` is the one the earlier draft omitted, and it is not optional.**
`black-translucent` without it produces a canvas that stops short of the Dynamic Island —
white bars top and bottom, which reads as "web page," not "app." The two tags are a pair.

References:
[Apple: Supported Meta Tags](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariHTMLRef/Articles/MetaTags.html) ·
[MDN: viewport meta](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/name/viewport) ·
[MDN: Web App Manifest](https://developer.mozilla.org/en-US/docs/Web/Manifest) ·
[MDN: manifest `display`](https://developer.mozilla.org/en-US/docs/Web/Manifest/Reference/display)

### 3d. Safe areas

With `viewport-fit=cover` the canvas extends under the status bar *and* under the home
indicator. Interactive elements must respect
[`env(safe-area-inset-*)`](https://developer.mozilla.org/en-US/docs/Web/CSS/env).

The Godot canvas fills the viewport, so this can't be solved in CSS alone — the "Tap to Start"
button in `main.tscn` and any future controls need bottom clearance inside the scene, or they
sit under the home indicator where taps are intercepted. Simplest approach: read the insets in
JS, pass them to the engine via `JavaScriptBridge`, and apply them as margins on the root
`Control`. Alternatively, keep all interactive UI in the middle 70% of the screen and accept
the constraint at design time.

**This is a design constraint for the mockup, not a polish item.**

### 3e. Hosting

Install requires a secure context. Firebase Hosting serves HTTPS by default, so this is
satisfied.

One thing to watch in `exports/firebase.json`: the catch-all rewrite

```json
"rewrites": [{ "source": "**", "destination": "/index.html" }]
```

Firebase applies rewrites only when no matching file exists, so `index.pck` / `index.wasm`
serve normally. But if a filename ever drifts, a missing asset returns **HTML with a 200**
instead of a 404, and Godot fails to boot with a confusing error rather than a clean
missing-file message. Worth remembering when debugging a blank canvas.
([Firebase Hosting config](https://firebase.google.com/docs/hosting/full-config))

## 4. Detecting install state

Used to decide whether to show the "add me to your home screen" hint.

```javascript
// True when running as an installed standalone web app.
// matchMedia is the standard check; navigator.standalone is a non-standard
// Apple property kept for older iOS.
function isInstalled() {
  return window.matchMedia('(display-mode: standalone)').matches
      || window.navigator.standalone === true;
}

function isIOS() {
  return /iPad|iPhone|iPod/.test(navigator.userAgent)
      || (navigator.platform === 'MacIntel' && navigator.maxTouchPoints > 1); // iPadOS
}

// iOS reports no beforeinstallprompt, so the hint is the only install affordance there.
if (isIOS() && !isInstalled()) {
  showAddToHomeScreenHint();
}
```

[MDN: `display-mode` media query](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/display-mode)

The `MacIntel` clause matters because iPadOS reports a desktop user agent by default.
`navigator.standalone` is Apple-proprietary and has no MDN page; it is documented only in
Apple's older Safari references.

## 5. The product constraint nobody wrote down

The install flow is a five-step manual sequence performed **once, in a dark concert hall, by a
patron under time pressure, possibly on congested venue wifi**.

A meaningful fraction of the audience will not complete it. Therefore:

* The app **must** degrade gracefully in a plain browser tab — address bar visible, reduced
  vertical space — and still be a good experience.
* Installed standalone is the *enhanced* path, not the required one.
* Anything that only works when installed is effectively optional for the concert.

This should be treated as a requirement for the `C1_T05` mockup.
